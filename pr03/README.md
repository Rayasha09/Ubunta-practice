Практическая работа №3. Процессы в Linux
Цель работы
Наблюдать процессы и их состояния средствами операционной системы; научиться создавать, ожидать и завершать процессы программно.
1. Дерево процессов
Файл ptree.py читает информацию из каталога /proc и отображает дерево процессов текущего пользователя. Для каждого процесса выводятся PID, состояние и RSS.

Запуск:
python3 ptree.py
2. Создание дочерних процессов
Файл runner.py создаёт N дочерних процессов с помощью os.fork(). Каждый дочерний процесс запускает переданную команду через os.execvp(). Родитель ожидает завершения процессов и выводит код возврата и время работы.

Пример запуска:
python3 runner.py 3 sleep 1
Результат: все три дочерних процесса завершились с кодом возврата 0. Время работы каждого составило примерно одну секунду.
3. Процесс-зомби
Файл zombie_demo.py создаёт дочерний процесс, который завершается раньше родителя. До получения статуса завершения через waitpid() дочерний процесс может отображаться в состоянии Z (<defunct>).

При проверке командой ps было обнаружено состояние Z+.
4. Процесс-сирота
Файл orphan_demo.py демонстрирует продолжение работы дочернего процесса после завершения родителя.

В эксперименте PID дочернего процесса оставался 26831, а PPID изменился с 26830 на 2682. Это показывает, что процесс был переподчинён другому процессу в системе.
5. Copy-on-Write
Файл cow_memory.py создаёт большой массив в родительском процессе, затем вызывает fork() и изменяет массив в дочернем процессе.

Полученные значения RSS:
- Родитель: 62392 KB.
- Ребёнок до изменения памяти: 59994 KB.
- Ребёнок после изменения памяти: 60368 KB.
RSS показывает объём резидентной памяти процесса. Эти измерения сами по себе не доказывают механизм Copy-on-Write напрямую.
Контрольные вопросы
1. Почему fork() возвращает два разных значения?

В дочернем процессе fork() возвращает 0, а в родительском — PID дочернего процесса. При ошибке возвращается -1.

2. Что изменится, если вызвать exec без предварительного fork()?

При успешном вызове exec текущая программа заменяется новой программой. Если вызвать exec непосредственно в родительском процессе, его прежний код перестанет выполняться.
Вывод
В ходе практической работы изучены дерево процессов Linux, создание дочерних процессов, ожидание завершения, состояния зомби и сироты, а также особенности памяти после fork().
